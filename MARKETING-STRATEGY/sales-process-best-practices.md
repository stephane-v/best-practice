# Sales Process Best Practices

## Introduction

A well-defined sales process transforms inconsistent selling into a repeatable, scalable system. This guide covers the complete sales cycle from lead qualification to closing deals, including frameworks, scripts, and best practices for maximizing revenue.

## The Sales Process Framework

```
┌─────────────────────────────────────────────────────────────────┐
│                    SALES PROCESS STAGES                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  PROSPECT → QUALIFY → DISCOVERY → PRESENT → HANDLE → CLOSE      │
│                                  OBJECTIONS                      │
│                                                                  │
├─────────────────────────────────────────────────────────────────┤
│  Find        Is this    Understand   Show      Address   Win    │
│  potential   a good     needs &      solution  concerns  deal   │
│  buyers      fit?       pain points                             │
└─────────────────────────────────────────────────────────────────┘
```

## 1. Lead Qualification

### Understanding Lead Types

```
Lead Lifecycle:
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│   LEAD   │ → │   MQL    │ → │   SQL    │ → │ CUSTOMER │
│          │   │ Marketing│   │  Sales   │   │          │
│          │   │ Qualified│   │ Qualified│   │          │
└──────────┘   └──────────┘   └──────────┘   └──────────┘
```

### BANT Qualification Framework

| Criteria | Questions to Ask |
|----------|-----------------|
| **B**udget | "What budget have you allocated for solving this problem?" |
| **A**uthority | "Who else is involved in this decision?" |
| **N**eed | "What's driving this initiative?" |
| **T**imeline | "When are you looking to implement a solution?" |

### MEDDIC Framework (B2B Enterprise)

| Element | Description | Key Questions |
|---------|-------------|---------------|
| **M**etrics | Quantifiable goals | "What metrics define success?" |
| **E**conomic Buyer | Final decision maker | "Who signs the contract?" |
| **D**ecision Criteria | Evaluation factors | "How will you evaluate options?" |
| **D**ecision Process | Steps to purchase | "What's your buying process?" |
| **I**dentify Pain | Business challenges | "What's the cost of not solving this?" |
| **C**hampion | Internal advocate | "Who's championing this internally?" |

### Lead Scoring Model

```
Lead Score Components:

Demographic Fit (40 points max)
├── Company size: 0-10 points
├── Industry match: 0-10 points
├── Job title/role: 0-10 points
└── Geography: 0-10 points

Behavioral Signals (40 points max)
├── Website visits: 0-10 points
├── Content downloads: 0-10 points
├── Email engagement: 0-10 points
└── Demo/trial requests: 0-10 points

Engagement Level (20 points max)
├── Meeting attendance: 0-10 points
└── Response time: 0-10 points

Scoring Thresholds:
├── 0-30: Cold lead (Marketing nurture)
├── 31-60: Warm lead (Marketing qualified)
├── 61-80: Hot lead (Sales qualified)
└── 81-100: Priority opportunity
```

## 2. Prospecting and Outreach

### Multi-Channel Outreach Strategy

```
Ideal Cadence (B2B):
Day 1:  Email #1 (Introduction)
Day 2:  LinkedIn connection request
Day 4:  Phone call #1 (Voicemail if needed)
Day 6:  Email #2 (Add value)
Day 9:  LinkedIn message
Day 11: Phone call #2
Day 14: Email #3 (Break-up email)
Day 18: Final attempt (Phone or email)
```

### Cold Email Framework

#### Structure
```
Subject: [Personalized, curiosity-driving]

Hi [First Name],

[Hook - Observation or trigger event about them]

[Problem - Pain point they likely experience]

[Solution - How you can help (briefly)]

[CTA - Single, clear ask]

[Signature]

P.S. [Additional value or social proof]
```

#### Cold Email Examples

**Trigger-Based:**
```
Subject: Congrats on the Series B, [Name]

Hi [Name],

Saw the news about [Company]'s Series B - congratulations!

With growth comes growing pains. Many companies at your stage
struggle with [specific problem].

We helped [Similar Company] solve this, resulting in [specific result].

Would you be open to a 15-minute call to see if we could help
[Company] achieve similar results?

[Your Name]
```

**Value-First:**
```
Subject: Quick idea for [Company]

Hi [Name],

I noticed [Company] is [doing something specific].

Based on what I've seen work at [Similar Companies], here's
a quick idea that might help:

[Specific, actionable tip]

If this resonates, I'd love to share 2-3 more ideas on a
brief call.

Worth a conversation?

[Your Name]
```

### Cold Calling Best Practices

#### Opening Script Framework
```
"Hi [Name], this is [Your Name] from [Company].

[Pattern interrupt - quick, unexpected statement]

The reason I'm calling is [1-sentence value prop].

Did I catch you at a bad time?"
```

#### Example Opening
```
"Hi Sarah, this is John from TechSolutions.

I just got off a call with your competitor Acme Corp,
and I saw something that made me think of you.

We help marketing teams reduce their customer acquisition
cost by an average of 30%.

Is this something worth a quick conversation?"
```

#### Handling Gatekeepers
```
Gatekeeper: "What's this regarding?"

Response options:
1. "It's regarding [specific business initiative].
   [Decision maker] and I have been trading messages."

2. "I'm following up on some research I did on
   [Company]'s [specific initiative]."

3. "I was hoping [Decision maker] could help me out.
   Could you transfer me please?"
```

### LinkedIn Outreach

#### Connection Request Template
```
"Hi [Name],

I noticed you're [relevant observation about their role/company].

I work with [similar role/industry] on [specific problem].

Would love to connect and share insights.

[Your Name]"
```

#### Follow-Up Message Template
```
"Thanks for connecting, [Name]!

I noticed [Company] is [observation].

I recently helped [Similar Company] achieve [specific result]
by [approach].

Would you be open to a brief call to explore if we could
help [Company] achieve similar results?

## 3. Discovery Calls

### Discovery Call Structure

```
┌─────────────────────────────────────────────────────────────────┐
│                    DISCOVERY CALL FLOW                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. OPENING (5 min)                                             │
│     └── Build rapport, set agenda                               │
│                                                                  │
│  2. CURRENT STATE (10 min)                                      │
│     └── Understand existing situation                           │
│                                                                  │
│  3. PAIN POINTS (10 min)                                        │
│     └── Identify challenges and impact                          │
│                                                                  │
│  4. DESIRED STATE (10 min)                                      │
│     └── Define goals and success metrics                        │
│                                                                  │
│  5. BUYING PROCESS (10 min)                                     │
│     └── Understand decision process                             │
│                                                                  │
│  6. NEXT STEPS (5 min)                                          │
│     └── Agree on action items                                   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### Discovery Questions by Category

#### Current State
- "Tell me about your current process for [X]?"
- "What tools/solutions are you using today?"
- "How long have you been doing it this way?"
- "What's working well about your current approach?"

#### Pain Points
- "What's not working as well as you'd like?"
- "If you could wave a magic wand, what would you change?"
- "What happens when [problem] occurs?"
- "How is this impacting your team/business?"
- "What does this cost you in terms of [time/money/opportunities]?"

#### Desired State
- "What does success look like for this project?"
- "What metrics would you use to measure improvement?"
- "Where do you want to be in 6-12 months?"
- "What's driving this initiative now?"

#### Decision Process
- "Who else needs to be involved in this decision?"
- "What's your timeline for making a decision?"
- "What's your budget range for a solution?"
- "What criteria will you use to evaluate options?"
- "Have you looked at other solutions?"

### SPIN Selling Framework

| Type | Purpose | Examples |
|------|---------|----------|
| **S**ituation | Understand context | "How many people are on your team?" |
| **P**roblem | Identify issues | "What challenges are you facing with X?" |
| **I**mplication | Explore impact | "What happens if this isn't solved?" |
| **N**eed-payoff | Highlight value | "How would solving this help you achieve Y?" |

### Active Listening Techniques

1. **Paraphrase**: "So what I'm hearing is..."
2. **Clarify**: "Can you tell me more about...?"
3. **Summarize**: "Let me make sure I understand..."
4. **Reflect feelings**: "It sounds like that's frustrating..."
5. **Ask follow-ups**: "You mentioned X, can you expand on that?"

## 4. Sales Presentations

### Presentation Structure

```
┌─────────────────────────────────────────────────────────────────┐
│                    PRESENTATION FLOW                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. RECAP & AGENDA (3 min)                                      │
│     └── Review discovery insights, set expectations             │
│                                                                  │
│  2. PAIN POINTS (5 min)                                         │
│     └── Mirror their challenges back to them                    │
│                                                                  │
│  3. SOLUTION OVERVIEW (10 min)                                  │
│     └── High-level how you solve their problems                 │
│                                                                  │
│  4. DEMO/DETAILS (15 min)                                       │
│     └── Show relevant features, use cases                       │
│                                                                  │
│  5. SOCIAL PROOF (5 min)                                        │
│     └── Case studies, testimonials                              │
│                                                                  │
│  6. PRICING & PROPOSAL (5 min)                                  │
│     └── Present options clearly                                 │
│                                                                  │
│  7. Q&A & NEXT STEPS (7 min)                                    │
│     └── Handle questions, agree on actions                      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### Demo Best Practices

#### Before the Demo
- Research their specific use case
- Prepare relevant examples/data
- Test all technology
- Have backup plans ready

#### During the Demo
- **Tell-Show-Tell**: Explain, demonstrate, reinforce
- Focus on their pain points, not all features
- Use their terminology and examples
- Pause for questions and engagement
- Watch for buying signals

#### Demo Mistakes to Avoid
- Showing every feature
- Going too fast
- Ignoring technical issues
- Talking more than listening
- Not customizing for the audience

### Proposal Best Practices

#### Proposal Structure
```
1. Executive Summary
   └── 1-page overview of solution and value

2. Understanding Your Needs
   └── Mirror their challenges and goals

3. Proposed Solution
   └── How you'll address their needs

4. Implementation Plan
   └── Timeline and process

5. Investment
   └── Pricing options clearly presented

6. Why Us
   └── Differentiators and proof points

7. Next Steps
   └── Clear call to action
```

#### Pricing Presentation

**Option 1: Good-Better-Best**
```
┌──────────────┬──────────────┬──────────────┐
│   STARTER    │   GROWTH     │  ENTERPRISE  │
│   $X/month   │   $Y/month   │   $Z/month   │
├──────────────┼──────────────┼──────────────┤
│ Feature A    │ Feature A    │ Feature A    │
│              │ Feature B    │ Feature B    │
│              │ Feature C    │ Feature C    │
│              │              │ Feature D    │

Present highest option first to anchor price expectations.

## 5. Handling Objections

### Objection Handling Framework (LAER)

```
┌────────────────────────────────────────────────────────────────┐
│                    LAER METHOD                                  │
├────────────────────────────────────────────────────────────────┤
│                                                                 │
│  L - LISTEN                                                     │
│      Let them fully express their concern                       │
│                                                                 │
│  A - ACKNOWLEDGE                                                │
│      Show you understand and empathize                          │
│                                                                 │
│  E - EXPLORE                                                    │
│      Ask questions to understand root cause                     │
│                                                                 │
│  R - RESPOND                                                    │
│      Address the real concern with evidence                     │
│                                                                 │
└────────────────────────────────────────────────────────────────┘
```

### Common Objections and Responses

#### Price Objections

**"It's too expensive"**
```
Response Framework:
1. Acknowledge: "I understand price is an important consideration."
2. Explore: "When you say too expensive, compared to what?"
3. Respond with value: "Let's look at the ROI. You mentioned
   [problem] costs you [X]. Our solution typically delivers
   [Y] return in [timeframe]."
```

**"We don't have the budget"**
```
Response Framework:
1. Acknowledge: "Budget constraints are real."
2. Explore: "Is this a timing issue, or is the total investment
   the concern?"
3. Options: Offer payment plans, phased approach, or starter
   package.
```

#### Timing Objections

**"Not right now / We're too busy"**
```
Response Framework:
1. Acknowledge: "I understand you have a lot on your plate."
2. Explore: "What would need to change for this to become
   a priority?"
3. Create urgency: "What's the cost of waiting another
   [timeframe] to solve this?"
```

**"Call me back in 6 months"**
```
Response Framework:
1. Acknowledge: "I can certainly do that."
2. Explore: "What will be different in 6 months that makes
   this a better time?"
3. Offer value: "In the meantime, would it be helpful if
   I sent you [valuable resource]?"
```

#### Competition Objections

**"We're looking at other options"**
```
Response Framework:
1. Acknowledge: "It makes sense to evaluate your options."
2. Explore: "What criteria are most important in your decision?"
3. Differentiate: "Where we typically stand out is [unique
   value]. How important is that to you?"
```

**"We're happy with our current solution"**
```
Response Framework:
1. Acknowledge: "I'm glad you have something working."
2. Explore: "If you could improve one thing about your
   current solution, what would it be?"
3. Plant seeds: "Many of our customers switched because of
   [specific improvement]. If that ever becomes relevant,
   would you be open to a conversation?"
```

#### Trust/Risk Objections

**"I need to think about it"**
```
Response Framework:
1. Acknowledge: "Of course, this is an important decision."
2. Explore: "What specific aspects do you need to think
   through? Is there anything I can clarify?"
3. Advance: "Would it help to schedule a follow-up call
   for [specific date] to discuss any questions?"
```

**"I need to talk to my team/boss"**
```
Response Framework:
1. Acknowledge: "That makes sense for a decision like this."
2. Explore: "What do you think their main concerns will be?"
3. Enable: "Would it help if I prepared a summary document
   for them? Or would a brief meeting with them be useful?"
```

### Objection Prevention

- Address common objections proactively in your presentation
- Use social proof before objections arise
- Build strong discovery to understand concerns early
- Create urgency throughout the process
- Ensure all stakeholders are involved early

## 6. Closing Techniques

### Closing Signals to Watch For

#### Verbal Signals
- Asking about implementation details
- Discussing internal logistics
- Asking about pricing/terms
- Using ownership language ("When we..." vs "If we...")
- Asking about support/training

#### Non-Verbal Signals
- Leaning forward
- Nodding along
- Taking notes
- Asking for materials to share

### Closing Methods

#### The Assumptive Close
```
"Based on what we've discussed, it sounds like the
[package name] is the right fit. I'll get the paperwork
started - should I send it to you or [other stakeholder]?"
```

#### The Summary Close
```
"So to summarize: you're looking to [solve problem],
achieve [goal], and you need a solution by [timeline].
Our [solution] addresses all of these. What questions
do you have before we move forward?"
```

#### The Alternative Close
```
"Would you prefer to start with the [Option A] or
[Option B] package?"

"Would you like to begin implementation this month
or next month?"
```

#### The Trial Close
```
"If we can address [remaining concern], would you be
ready to move forward?"

"On a scale of 1-10, how confident are you that this
is the right solution? What would make it a 10?"
```

#### The Urgency Close
```
"The [special offer/pricing] is available until
[date]. To lock this in, we'd need to finalize
by [date]. Does that work for your timeline?"
```

### Closing Checklist

```markdown
Before Asking for the Close:
□ All stakeholders have been engaged
□ Key decision criteria have been addressed
□ Budget has been confirmed
□ Timeline has been agreed upon
□ Objections have been handled
□ Value has been clearly demonstrated
□ Prospect has shown buying signals
```

## 8. Sales Forecasting

### Forecasting Categories

| Category | Definition | Confidence |
|----------|------------|------------|
| **Commit** | Will close this period | 90%+ |
| **Best Case** | Likely to close | 70-89% |
| **Pipeline** | Possible to close | 30-69% |
| **Upside** | Could close if everything goes well | < 30% |

### Forecast Calculation

```
Weighted Pipeline Forecast:
(Commit × 90%) + (Best Case × 70%) + (Pipeline × 40%) + (Upside × 10%)

Example:
Commit:    $100,000 × 90% = $90,000
Best Case: $200,000 × 70% = $140,000
Pipeline:  $300,000 × 40% = $120,000
Upside:    $100,000 × 10% = $10,000
                            ─────────
Total Forecast:             $360,000
```

### Forecast Accuracy Metrics

```
Forecast Accuracy = 1 - |Actual - Forecast| / Forecast

Example:
Forecast: $400,000
Actual: $380,000
Accuracy: 1 - |$380,000 - $400,000| / $400,000 = 95%

Target: > 90% accuracy
```
